# E7. 서브에이전트용 — 작업 지시 (v0.2)

> 결정 007의 원인 조사를 서브에이전트에 맡겼다면 이렇게 썼어야 한다는 예시입니다.

## 작성 메모 (본문 아님)

```
독자:      A2 서브에이전트 (탐색 전용)
읽는 목적: 좁은 조사 하나를 끝내고 결과만 돌려준다
읽는 상황: 대화 맥락 없음. 이 브리프가 아는 것의 전부
아는 것:   C# · Unity 일반. 이 프로젝트, XRI 버전, 내가 이미 본 것은 모름
성공 기준: 다시 묻지 않고 일을 시작하고, 내가 바로 검증할 수 있는 형태로 돌려준다
```

**라운드 1에서 바꾼 것 · 바꾸지 않은 것**
- E4와 같은 이유로 AI용 형식(목표 · 볼 곳 · 가설 · 돌려줄 것)은 그대로 두었습니다. 서브에이전트가 범위를 벗어나지 않게 하려면 이 칸들이 필요합니다.
- 다만 라운드 1의 "처음 보는 사람이 알아듣게" 원칙은 AI에게도 똑같이 적용됩니다. 그래서 목표 문장에 **왜 이 조사가 필요한지**를 풀어 썼고, "덮어쓴다"처럼 맥락을 알아야 하는 줄임말을 무엇이 무엇을 덮어쓰는지로 풀었습니다.
- 돌려받은 결과는 사람용 문서에 그대로 옮기지 않습니다. 사람용 문서는 사용자 목소리로 다시 씁니다.

## 본문

```
목표: XR Interaction Toolkit 3.5.1에서 손이나 컨트롤러가 XRGrabInteractable을 놓을 때,
던져진 오브젝트의 Rigidbody 속도가 어디서, 어떤 순서로 정해지는지 찾아 주세요.

왜 필요한가: 다트를 놓는 순간 속도를 조금 고치고 싶은데, selectExited 이벤트에서 속도를 바꾸면
나중에 XRI가 자기 계산값으로 다시 써서 바꾼 값이 사라지는 것 같습니다.
어느 시점에 코드를 넣어야 XRI가 다시 쓰지 않는지 정하려는 조사입니다.

볼 곳: Library/PackageCache/com.unity.xr.interaction.toolkit@*/Runtime/
       버전 폴더가 3.5.1인지 먼저 확인해 주세요. 인터넷 예제와 2.x 문서는 API가 달라서 보지 않습니다.
보지 않을 곳: Assets/Samples, Assets/XRI_Examples (예제 코드라 기준이 아닙니다)

가설 (확인되지 않음): 놓은 프레임의 LateUpdate에서 XRI가 속도를 다시 쓰고,
그 직전에 조준 보조 인터페이스 같은 것을 호출하는 것 같습니다.
이 가설과 맞지 않는 코드가 있으면 그것도 꼭 알려 주세요.

돌려줄 것 (300단어 이내):
1. 속도가 정해지는 메서드들의 호출 순서 — 파일 경로:줄 번호와 핵심 줄 인용
2. 사용자 코드가 끼어들 수 있는 지점(인터페이스 · 이벤트 · 설정 값)과, 각각 나중에 XRI가 다시 쓰는지
3. 확실하지 않은 부분은 "추측"이라고 표시
```
