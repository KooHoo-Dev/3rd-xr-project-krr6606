## 2. 단계

각 단계가 끝날 때마다 사용자에게 diff를 보여 주고 확인받는다. 커밋은 문서별로 나눈다.

### 1단계 — 사실 확인 (사용자 답변 필요, 30분)
글을 다듬기 전에 3장의 "확인할 사실"부터 답을 받는다. 틀린 사실 위에 문장을 다듬으면 두 번 일하게 된다. 답이 없는 사실은 본문에서 빼거나 작게 쓴다.

### 2단계 — 문체 다듬기 (구조는 그대로, 위험 낮음)
문서 하나씩, **하이브 퍼지 → 냥코 → 시장에 가면** 순서로 한다. 가장 짧은 문서부터 하는 이유는 사용자가 결과 톤을 먼저 확인하고 나머지에 반영하기 위해서다.
- 라벨을 빼고 이어지는 문장으로 쓴다 (~습니다, 저/제가).
- 화살표 요약을 문장으로 바꾼다. 다이어그램과 코드 주석 안의 화살표는 그대로 둔다.
- 문서가 자기를 설명하는 문장을 지운다.
- 용어는 처음 나올 때 한 번 풀어 쓴다. 특히 개요의 IK, FSM, 서버 권위, WebSocket.
- 과장을 실제 크기로 줄인다. 예: 냥코 문제 해결 1, 시장에 가면 csproj 문제, 하이브 퍼지 측정 결과.
- 코드는 바꾸지 않는다. 코드 발췌 범위를 줄이는 것은 4단계에서 정한다.

### 3단계 — 구조 정리 (사용자가 골라야 함)
- **세 문서 공통:** 5장 안에 섞여 있는 "문제 해결"을 회고 앞의 독립된 장으로 뺄지 정한다.
