# E1. 채용 담당자용 — 포트폴리오 요약 카드

> **같은 사실 묶음 (E1~E4):** 손 추적 도입 · 손 잡기 각도 · 던지기 보정 철회와 조준선. 근거: [결정 006](../../decisions/006-손-추적-도입.md), [결정 007](../../decisions/007-손-잡기-각도와-던지기-보정.md), [devlog 11-20](../../devlog/2026-11-20.md)

## 독자 카드
```
독자:      H1 채용 담당자 (비개발)
읽는 목적: 기술 면접에 넘길지 판단
읽는 상황: 포트폴리오 PDF를 훑음, 30초
아는 것:   게임은 앎. Unity · XRI · 손 추적 API는 모름
성공 기준: "무엇을 · 누가 · 돌아가는가"와 이 사람이 판단한 장면 하나를 말할 수 있다
```

## 설계 메모
- **넣은 것:** 한 문장 소개, 기간 · 플랫폼, 내 역할, 판단한 장면 하나(컨트롤러 → 손), 영상 자리.
- **뺀 것:** `IXRAimAssist`, Pinch Grab Pose, 각도 값 (45, -45, 0), 속도 계산. 이 독자에게는 판단에 쓰이지 않는다.
- **모양:** 표 + 세 줄. 문단 없음. 숫자는 "60초", "8일"처럼 비개발자도 읽는 것만.
- **비운 곳:** 인원 · 역할 · 영상 · 테스트 반응은 기록에 없어서 `[확인 필요]`로 남겼다. 그럴듯하게 채우지 않는다.

// 나쁘지는 않지만, 문서를 쓰는 사용자가 강조하고 싶은 부분과 채용 담당자가 확인하고 싶은 부분은 이런 내용이 아니야.

- **써 보고 아니면 되돌렸습니다.** 던지는 방향을 자동으로 보정하는 기능을 넣었다가, 직접 테스트한 뒤 빼고 날아갈 길을 보여주는 조준선으로 바꿨습니다.
- **AI와 역할을 나눠 일했습니다.** 원인 조사와 선택지는 AI에게 받고, 무엇을 할지는 제가 정했습니다. 모든 결정은 기록으로 남겼습니다.
