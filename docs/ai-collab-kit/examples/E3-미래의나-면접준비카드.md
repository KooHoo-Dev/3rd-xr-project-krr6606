# E3. 미래의 나용 — 면접 준비 카드 (v0.2)

## 작성 메모 (본문 아님)

```
독자:      H3 미래의 나 (면접 전날)
읽는 목적: 예상 질문에 바로 답하고, 이어지는 질문에도 근거를 댄다
읽는 상황: 질문 제목을 훑으며 찾기. 질문 하나에 10초
아는 것:   대략은 기억하지만 수치 · 이름 · 이유가 흐림
성공 기준: 소리 내어 읽으면 그대로 면접 답이 된다
```

**라운드 1에서 바꾼 것**
- 이 문서에는 피드백이 없었지만, 사람이 읽는 문서라서 같은 원칙을 적용했습니다.
- "A." "근거:" "꼬리:" 같은 라벨을 없애고, 면접에서 말하는 그대로의 ~습니다 체 답으로 바꿨습니다. 근거 위치는 답 끝에 괄호로 붙였습니다.
- 이어지는 질문은 "이어서 ~라고 물으면"으로 풀어 썼습니다.
- 자세한 설명은 E2에 있으므로 여기서는 반복하지 않았습니다.

**본문에서 뺀 것 — 확인해 주세요**
- "만들었다가 버린 기능" 질문에서 보정을 뺀 이유. 이유를 모른 채 외우면 면접에서 무너지므로, 이유 없이 답을 지어내지 않았습니다.

## 본문

### 왜 손 추적을 넣었나요?

컨트롤러는 실제 다트와 쥐는 모양도 무게도 달라서, 던지는 손맛이 살지 않았기 때문입니다. 이 게임은 던지는 맛이 핵심이라 마감이 사흘 남았어도 바꾸기로 했습니다. (결정 006, 2026-11-20)

이어서 "마감 직전인데 위험하지 않았나요?"라고 물으면, 컨트롤러도 계속 쓸 수 있게 두어서 손 던지기가 잘 안 돼도 시연은 할 수 있게 했고, 본 씬이 아니라 복제한 테스트 씬에서 먼저 확인했다고 답합니다.

### 손으로 잡을 때 문제는 없었나요?

다트 끝이 위를 향하는 문제가 있었습니다. 다트를 잡는 기준점이 컨트롤러 자세에 맞춰져 있어서 손의 핀치 자세와 각도가 달랐던 것이라, 손 쪽에만 회전값을 더해 (45, -45, 0)으로 맞췄습니다. (결정 007)

이어서 "원인은 누가 찾았나요?"라고 물으면, XR Interaction Toolkit 소스에서 원인을 찾은 것은 AI였고, 각도는 제가 Link로 플레이하면서 직접 돌려 보며 정했다고 답합니다.

### 만들었다가 뺀 기능이 있나요?

세게 던질수록 날아가는 방향을 위로 올려 주는 보정을 넣었다가, 직접 던져 본 뒤에 빼고 날아갈 길을 보여 주는 조준선으로 바꿨습니다. (결정 007)

이어서 "그 보정은 어디에 넣었나요?"라고 물으면, XR Interaction Toolkit이 손을 놓은 뒤 LateUpdate에서 속도를 다시 정하기 때문에 놓는 순간의 이벤트에서는 덮어써지고, 그래서 속도를 정하기 직전에 불리는 `IXRAimAssist`에 넣었다고 답합니다.

### AI가 만든 코드는 어떻게 확인했나요?

Link로 기기에서 직접 잡고 던져 보면서 확인했고, 기대와 다르면 값을 고치거나 기능을 뺐습니다. 커밋마다 AI가 쓴 코드인지 제가 쓴 코드인지 표시해 두어서, 어느 부분이 누구 작업인지도 바로 찾을 수 있습니다. (devlog 2026-11-20)
