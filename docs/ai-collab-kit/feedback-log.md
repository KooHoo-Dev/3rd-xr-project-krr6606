# 피드백 기록

> **읽는 이:** 다음 세션 Claude(A1) — 키트를 고치기 전에 지난 피드백을 확인한다. 사용자 — 무엇이 반영됐는지 확인한다.
> 한 라운드 = 사용자 피드백 1회. 피드백은 사용자 말을 요약하되 뜻을 바꾸지 않는다. 반영하지 않은 것은 이유를 적는다.

## 라운드 0 — 시작 (2026-11-23)

**사용자 요청 (요약)**
1. 프로젝트 중간중간 포트폴리오 재료 수집을 자동으로 하고 싶다. 앞으로 AI와 프로젝트를 시작할 때부터 포트폴리오 작업과 프로젝트를 동시에 하도록 CLAUDE 문서 초안을 써 달라.
2. Claude가 쓰는 문서는 문서 목적에 맞는 작성법, 읽는 주체가 사람인지 AI인지, 어떤 사람이 무엇을 위해 읽는지에 대한 고려가 약하다. 독자 페르소나를 여러 개 만들고 여러 주제의 예시 문서를 써 보면 사용자가 피드백하겠다.
3. 이 과정을 다른 세션에서도 알 수 있게 문서를 쓰고 고쳐 나가라.

**Claude가 만든 것 (v0.1)**
- [writing-guide.md](writing-guide.md) — 독자 카드, 사람 vs AI 독자, 문서 종류별 작성법, 자가 점검
- [personas.md](personas.md) — H1~H5, A1~A2
- [examples/](examples/) — E1~E7 (E1~E4는 같은 사실을 독자만 바꿈)
- [CLAUDE.template.md](CLAUDE.template.md), [templates/](templates/) — 새 프로젝트용

**Claude가 정한 것 (사용자 확인 필요)**
- 재료집은 **사실과 위치만** 모으고 프로젝트 문서 본문은 사용자가 쓴다. 근거: 포트폴리오 템플릿의 원칙("수강생 문서를 대신 고쳐 쓰지 않는다"). 사용자가 Claude 초안을 원하면 바꾼다.
- 키트 위치를 이 프로젝트의 `docs/ai-collab-kit/`로 했다. 여러 프로젝트에서 쓸 원본을 따로 둘지(별도 레포 등)는 사용자가 정한다.
- 자동화는 CLAUDE.md 규칙으로만 했다. 세션 끝에 재료집을 강제로 확인시키는 훅(hook) 같은 장치는 아직 넣지 않았다.

**사용자 피드백:** 라운드 1에서 받음.

## 라운드 1 — 2026-11-23

**사용자 피드백.** 사용자가 예시 문서 사이에 직접 적었습니다. 원문은 변형 없이 [feedback/round-1-원문.md](feedback/round-1-원문.md)(F1-1~F1-7)에 있고, 피드백이 달린 v0.1 파일 전체는 [feedback/round-1-원본/](feedback/round-1-원본/)에 있습니다. 아래는 Claude가 요약한 것입니다.
- F1-1 (E1): 손 추적 과정은 사용자가 강조하려는 것도, 채용 담당자가 확인하려는 것도 아니다.
- F1-2 (E2): ~했다 체는 딱딱하므로 ~습니다로 써야 한다. 문장이 끊기고 서로 이어지지 않아 사람이 쓴 글 같지 않고, 재미가 없어 읽히지 않는다.
- F1-3 (E2): 현업자에게 별것 아닌 문제를 과장하면 마이너스다. 어색한 요약은 없는 편이 낫다.
- F1-4 (E2): "A → B" 같은 요약은 처음 읽는 사람이 무슨 말인지, 무엇을 위한 결정인지 알 수 없다.
- F1-5 (E5): 사용 안내에는 스크린샷이 있으면 좋다.
- F1-6 (E6): 사람이 쓴 것처럼 읽혀야 한다. `질문:`, `맥락:`, `[확인 필요:]` 같은 메타 내용은 있으면 안 된다.
- F1-7 (E6): "~만 알려 주시면 됩니다"는 AI 입장의 말이다. **사람에게 쓰는 모든 문서는 사용자가 쓰는 글을 Claude가 대필하는 것이다.**

**반영한 것 (v0.2)**
- [writing-guide.md](writing-guide.md): 0-1절 "사람에게 쓰는 문서는 사용자의 글이다"를 새로 넣었습니다(대필 원칙, ~습니다 체, 이어지는 문장, 라벨 금지, 과장 금지, 화살표 요약 금지, 모르는 사실은 빼거나 묻기). 4절 문서 종류 표와 5절, 6절 자가 점검도 고쳤습니다.
- [personas.md](personas.md): H1에 라운드 1에서 배운 것을 적었습니다.
- [examples/](examples/): E1~E7을 모두 새로 썼습니다. E1은 강조점을 바꿨고, E2·E3·E6은 문체와 구성을 바꿨습니다. E5에는 스크린샷 자리 4개를 넣었고, E4·E7은 형식을 유지하되 고쳤습니다.
- 기억 메모에 "사람용 문서는 대필" 피드백을 따로 저장했습니다. 이 프로젝트의 모든 문서 작업에 적용됩니다.

**반영하면서 Claude가 해석한 것 (사용자 확인 필요)**
1. 대필 원칙과 라벨 금지는 **남에게 보여 줄 완성 글**에 적용하고, devlog · 결정 기록 · 재료집 같은 작업 기록과 AI용 문서(E4, E7, CLAUDE.md)에는 적용하지 않았습니다.
2. E1의 새 강조점(완성 결과물, 기술, 직접 만든 범위, AI와 일하는 방식)은 Claude의 가정입니다. 실제로 강조하고 싶은 것을 알려 주시면 고치겠습니다.
3. 모르는 사실은 본문에서 빼고 작성 메모에 모았습니다. 그래서 E2의 보정을 뺀 이유처럼 꼭 필요한 내용이 빠진 상태입니다.

**아직 못 한 것**
- E5 스크린샷 4장은 사용자가 찍어야 합니다(목록은 E5 작성 메모에 있습니다).
