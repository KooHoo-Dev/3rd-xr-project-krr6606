# 008. 손 던지기 다트 → 고정형 계곡 새총 + 조약돌

- 날짜: 2026-11-21
- 결정한 사람: 사용자 (Claude는 원인 분석 · 선택지 · 추천 제시)
- 태그: `#AI리더십` `#구조화`
- 관련: [002](002-물풍선-기획-전환.md), [006](006-손-추적-도입.md), [007](007-손-잡기-각도와-던지기-보정.md)
- 상태: 초안 — 사용자 확인 전

## 문제 (사용자가 Quest에서 직접 테스트하고 관찰)
1. 손으로 잡고 던지면 원하는 방향 · 목표로 던지기 어렵다.
2. 손을 놓았는데 다트가 손가락에 잠시 붙어 있는 경우가 있다.
3. 테스트용 큐브를 원거리에서 집어 움직이는 것이 다트 던지기보다 더 재미있다.

## 원인 분석 (Claude 추론, 기기 검증 전)
- 조준선은 직선인데 다트는 중력으로 떨어진다. 10 m/s로 5 m를 던지면 약 1.2 m 떨어진다.
- `Throw Smoothing Duration` 0.25초가 손목 튕김(약 0.1~0.15초)보다 길어서, 팔을 휘두르는 앞부분이 평균에 섞인다.
- `Dart.Throw()`의 추가 힘이 손 이동 방향이 아니라 다트가 향한 방향으로 더해진다.
- 손 추적의 놓기 판정(집기 강도 해제 기준값)이 늦고, 빠르게 휘두르면 추적이 흔들린다.
- 기획 관점: 던지기는 놓는 한순간에 결과가 정해지는데, 시스템 오차가 실력보다 커서 연습해도 늘지 않는다. 큐브 잡기는 계속 조종하면서 결과를 바로 보므로 재미있다.

## 선택지
| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| 다트 유지 + 수치 조정 · 조준 보정 | 마감 위험이 가장 적음 | 놓는 판정 지연과 "연습해도 안 느는" 느낌은 남음 |
| **A. 고정형 Y자 나무 새총 + 조약돌 (채택, Claude 추천과 같음)** | 계곡 테마와 바로 이어짐, 관통 규칙 유지, 에셋 단순(고무줄은 LineRenderer) | 다트 에셋 · 이름을 버림 |
| B. 대형 물풍선 런처 + 작은 물풍선 | 물풍선끼리 맞히는 재미 | 관통이 어색해서 규칙을 바꿔야 함 |
| C. 받침대 위 나무 쇠뇌 + 다트 | 다트 에셋 · 이름 재사용, 관통이 가장 자연스러움 | 여름 계곡과 어울림이 약함 |

## 결정
A. 손으로 던지는 다트는 버린다. 손이 닿지 않는 곳에 고정된 새총의 주머니를 레이로 잡아 당겼다 놓아 조약돌을 쏜다.
- 발사 속도는 손 속도가 아니라 당긴 방향 · 거리로 정한다. 그래서 놓기 전에 포물선 궤적을 정확히 보여줄 수 있다.
- 탄환(돌멩이)은 풍선을 터트리고도 계속 날아간다 (일렬 관통 규칙 유지).

## 결정 보완 (2026-11-21, 사용자 결정): 손에 드는 새총
- 고정형 대신 **한 손(왼손)으로 새총을 쥐고 다른 손으로 주머니를 당긴다.** 실제 새총과 같아서 납득감이 가장 크다.
- 새총은 받침대 위에 두고, 레이로 끌어와 주먹 쥐기로 잡는다. XRI 3.5.1 기본 입력에서 손 `Select`는 집기와 주먹 쥐기(graspFirm) 둘 다에 연결되어 있다.
- 주머니 당기기 방식:
  - 처음에는 손 이동량에 배율을 곱하는 방식(사용자 선택)이었다. 고정형에서 레이 끝이 손목 떨림을 키우는 문제를 피하려는 것이었다.
  - 손에 들면 손 1:1 추적으로 바꾼다.
- 고정형은 대안으로 남긴다. 위험(추측, 기기 확인 필요): 조준할 때 당기는 손이 쥔 손을 가려 추적이 끊길 수 있다.
- 에셋: `Tools/AssetGen/make_slingshot.py`로 새총 · 주머니 · 고무줄을 만든다.

## 결정 보완 2 (2026-11-21, 사용자 결정): 에셋 품질 · 탄환을 보석으로
첫 미리보기를 보고 사용자가 세 가지를 고치기로 했다.
1. 새총은 로우폴리가 아니어도 된다 → 더 고품질로 만든다. 나뭇결 · 옹이, 손잡이에 나선으로 감은 가죽, 갈래 끝에 감은 고무줄을 넣었다.
2. 고무줄이 새총에 붙어 있지 않아 어색했다 → 고무줄을 LineRenderer 대신 **관 모양 메시(Band.fbx)**로 만든다. 갈래 끝에 감긴 자리에서 주머니 매듭까지 잇는다. Unity에서는 길이 방향(Z) 스케일을 늘려 당김을 표현한다.
3. 조약돌 대신 **보고 싶고 개성 있는 보석 탄환 14종**으로 바꾼다. 옥 · 보석 재질에 은은하게 빛나는 환상적인 느낌을 낸다 (`make_gems.py`, `gem_geo.py`).
- 보석 종류별 게임 효과(점수 · 능력 차이)는 범위 밖이다. devlog `나중에`에 적는다.

## 결정 보완 3 (2026-11-21, 사용자 결정): 보석 취소 → 모양이 다른 돌멩이
- 보석을 두 번 다시 만들었다. 메시는 실제 브릴리언트 컷 구조로 바꿨고, 셰이더는 굴절 · 분산 · 조명별 섬광을 넣었고, 보석 전용 스튜디오 테스트 씬도 만들었다.
- 그래도 사용자는 "품질을 올려도 원하는 모습이 나오지 않을 것 같다"고 판단해 **보석을 모두 취소**했다.
- 보석 메시 · 재질 · Gem 셰이더 · 재질 도구 · 테스트 씬 도구 · 테스트 씬 · 회전대 스크립트를 모두 삭제했다. 이 파일들은 커밋한 적이 없다.
- 대신 **모양이 각기 다른 돌멩이 10종**을 쓴다 (`stone_geo.py`, `make_stones.py`).
  - 모양: 물수제비 · 달걀 · 세모 · 길쭉한 · 콩 · 각진 · 엄지 자국 · 울퉁불퉁 · 물방울 · 석영 줄무늬
  - 색은 공용 팔레트이고, 얼룩 · 드문 점 · 석영 띠로 하나하나 개성을 준다.
- 교훈 (#AI리더십): 보는 맛을 좌우하는 시각 요소는 구현에 앞서 레퍼런스 이미지로 목표를 먼저 합의하는 편이 낫다. 이번에는 미리보기를 본 뒤에야 방향이 갈렸다.
